## Phase 3 - Local LLM - PASSED (WebGPU-capable Chrome)

The selected runtime is WebLLM 0.2.85 (Apache-2.0), which uses WebGPU and supports Cache API storage. The selected prebuilt model is SmolLM2-360M-Instruct-q4f16_1-MLC (Apache-2.0); its Hugging Face repository reports 207 MB total and WebLLM metadata estimates 376.06 MB of VRAM with `shader-f16` required. The browser must provide a usable WebGPU adapter with that feature. Chrome's official documentation lists WebGPU support for compatible Chrome platforms; WebKit lists WebGPU in Safari 26. Capability is checked at runtime because support also depends on GPU, OS, browser configuration, and secure context. **Provider and user disclosures:** Validation sends only a model-list request directly to the selected provider; no Tutor prompt is sent. Anthropic's [TypeScript SDK](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/typescript) disables browser use by default because credentials can be exposed; its API may also block browser requests for some organizations, including those with ZDR arrangements ([CORS/data retention](https://platform.claude.com/docs/en/build-with-claude/api-and-data-retention)). Provider docs do not establish that browser-stored keys are secure or guarantee CORS behavior for all accounts. A browser CORS/network failure is reported as unverified, not as an invalid key. The UI links provider-specific security, data terms, and billing information. Key validation is not inference and does not verify generation access, quota, or billing state.

Recognition speech-start is treated as a candidate; non-echo interim/final recognition or sustained analyser activity confirms the interruption, avoiding immediate cancellation from a transcript matching Tutor output. Track failures fall back honestly and disable barge-in.
